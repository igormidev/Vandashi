That license does not replace the separate terms of dependencies, fonts, icons, generated-project vendor files, or locally installed tools. The attributions below describe the actual implementation and package versions reviewed on September 23, 2026; they do not assert endorsement by an upstream project.

The distribution includes `THIRD_PARTY_LICENSES.txt` with original license and notice text, `LICENSE.electron.txt`, and Electron's `LICENSES.chromium.html`. The generator reads the installed production dependency tree from `package-lock.json`, preserves text bytes, groups identical notices, and records their sources and SHA-256 hashes. It fails when an installed package has neither a notice file nor a reviewed source record for its exact version. Run `node scripts/generate-notices.mjs` after `npm ci` on the target platform before packaging.

## ExifTool and native dependencies

The macOS/Linux metadata package is `exiftool-vendored.pl` 13.59.2, carrying ExifTool 13.59. Its source states copyright 2003–2026 Phil Harvey and redistribution under the same terms as Perl: the Artistic License or GPL. The package wrapper's MIT label does not replace that statement. The Artistic text, original README, vendor manifest and package-supplied stdin-EOF patch are retained. The manifest identifies the upstream archive and SHA-256, and the distributed Perl source remains in the package. Vandashi has not edited that source or patch.

The Windows optional package `exiftool-vendored.exe` 13.59.2 was inspected by downloading its exact lockfile archive and verifying its integrity, without running it. It includes a separate Perl/launcher LICENSE and `Licenses_Strawberry_Perl.zip`. The generator incorporates those original archive entries on Windows. Windows runtime behavior is a separate platform test; an archive inspection is not a runtime test.

Hyperframes brings in `sharp` 0.35.4 and native libvips packages. On the reviewed macOS ARM64 installation, `@img/sharp-libvips-darwin-arm64` 1.3.3 carries libvips 8.18.6 and a `versions.json` list of linked components. Its actual README declares LGPLv3 for libvips and several linked libraries, alongside MPL-2.0, MIT, BSD, FreeType and other component terms. `@img/sharp-wasm32` 0.35.4 also declares Apache-2.0, LGPL-3.0-or-later and MIT. Windows and Linux packages carry their own component tables; the generator reads those target-specific records rather than applying the macOS table to them.

The generated bundle retains native component tables, exact versions and GPLv3/LGPLv3 texts. The [matching sharp-libvips packaging source](https://github.com/lovell/sharp-libvips/tree/v1.3.3) records the build process and [upstream component terms](https://github.com/lovell/sharp-libvips/blob/v1.3.3/THIRD-PARTY-NOTICES.md). A notice bundle alone does not provide the corresponding source or demonstrate every native-library redistribution condition. An installer release that ships these binaries must retain the native notices and arrange the applicable corresponding-source/replacement materials for the exact components being distributed. This repository has not assembled or published a complete native corresponding-source archive; the external upstream links are provenance, not a claim that this release work is already complete.

## Notice coverage and updates

The macOS ARM64 audit found 313 installed production packages, including optional native packages present on this machine. The generated inventory supplies the complete current list; the direct-dependency table is not a substitute for it. Packages absent because they target another OS/architecture are not claimed as installed. Packaging should run on its target platform so Windows ExifTool and native-library notices are selected correctly.

Five published archives (`fontkit` 2.0.4, `bpm-detective` 2.0.5, `react-remove-scroll-bar` 2.3.8, `brotli` 1.3.3 and `dfa` 1.2.0) declare MIT in their package metadata and README but omit a complete license/copyright file. The reviewed records preserve both original files and an unchanged SPDX MIT template. Template placeholders are not substituted with invented copyright holders or years. This records the available upstream declaration; it does not pretend that an absent upstream copyright notice was found.

`third-party/sources.json` records supplemental source URLs, exact versions and content hashes. Source files in that directory are copied verbatim and excluded from formatting. These records include the matching upstream Puppeteer licenses omitted from its published archives, Hyperframes' root license, reference-project attribution and native-license texts. New versions with missing notices require a new reviewed source record; the generator does not silently reuse unrelated license text.

Keep dependency-package notices, GSAP's generated-project header, original ExifTool source/patch records and Electron's Chromium notices when producing installers. Re-run the generator after dependency changes, verify the notice files in the packaged application, and update this version/provenance record when the direct dependencies or copied vendor assets change.
