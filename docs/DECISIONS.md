## Data and operation contracts to settle before feature coding

1. Versioned brand, video packaging, launch, asset, and app-preference schemas with validation and migration. Stable IDs must not rely solely on editable display names.
2. Repository registry and operation journal: each operation records scope, phase, conversation identity, selected model/effort, file baseline, related repositories, commits, and recovery status.
3. One AI coordinator with explicit idle, preparing, running, committing, failed, canceled, and recovering states. Locks derive from coordinator state and unsaved-draft ownership.
4. Storage port for paths/files/metadata and process ports for Git, Codex, and Hyperframes; renderer consumes typed feature APIs instead of building shell commands.
5. Chat-scope registry defining role, main target, mandatory reads, optional references, mention sources, and writable roots. Every turn reconstructs guidance from current paths/state.
6. Standard draft transaction for brand/packaging/metadata, controlled staged-script handoff, and manual-Studio reconciliation. Each needs cancellation and interrupted-run recovery.
7. File/commit/diff events invalidate affected views: editor buffers, assets, mention picker, preview, history, packaging, and launch status.
8. Media-resource protocol/URL validation for local display and a loopback-only Studio lifecycle. Untrusted web content must not gain app filesystem/process privileges.
9. Capability-aware release manifest containing exact selected media and reviewed packaging. A draft prompt or export file does not equal publication.
10. Verification records link requirement IDs to real implementation/tests and distinguish mocked protocol tests from actual external integration evidence.

## Storage implementation decisions (2026-09-23)

- **Registered roots and paths:** application data stores the brand registry, preferences, and conversation/checkpoint mappings. Workspace paths are checked against real filesystem roots and every existing ancestor, rejecting symlinks that escape. Portable names reject reserved device names, separators, traversal, control characters, and trailing dots. Selected import-source authorization belongs to the desktop file-picker boundary; workspace authorization is enforced again in storage.
- **Repository scope:** `brand_identity` and each video/clip retain independent repositories. `shared_assets` is an additional independent repository because its content lives outside `brand_identity` yet must be versioned and committed. A video's `.gitignore` excludes `clips/` to avoid accidental embedded gitlinks. Project `.git` must be a real local directory, not a redirecting symlink or gitdir file.
- **Git execution:** every command uses an argument array, no shell. Inherited `GIT_*` routing variables and project hooks are disabled for product-owned data commits; implementation-source commits still follow the development quality gates. Restore creates a backup reference and a new restoration commit instead of rewriting history. The exact-file restore helper exists only for controlled staged-script rollback and preserves unrelated changes.
- **Atomic files and stale drafts:** writes use same-directory exclusive temporary files, flush before rename, and clean temporary files on errors. Manual saves compare a content-derived workspace revision and validate every target against the editable-document set before writing. The registry/session update queue prevents lost concurrent updates.
- **YAML repair:** validated schemas recover only the affected file from its latest valid Git version. Invalid text is retained under `.vandashi-recovery/` before replacement. Read/open may repair YAML or synchronize assets but never commits; the application owns entry-time and AI-completion commit reconciliation. Thus periodic UI refresh cannot accidentally commit Studio drafts or staged script work.
- **Shared assets:** authoritative originals remain in the shared repository. Each project's `video_assets/_shared/` contains managed copies with a hash manifest at `video_assets/.vandashi-shared.json`. Updates copy only verified unchanged managed destinations. A locally edited copy yields a conflict instead of being overwritten. Removed shared originals remain as snapshots in older projects to avoid silently breaking timelines.
- **Asset identity and metadata:** adjacent `<filename>.vandashi.json` stores title, description, normalized unique tags, original-byte SHA-256, post-metadata content hash, and embedding result/warning. Original hashes support dedup even after metadata changes. A later external byte edit invalidates that equivalence. File metadata is indexed recursively and cached by size/mtime/ctime; folder-relative paths preserve navigation and disambiguation.
- **Embedded metadata:** media is edited through a disposable copy. Verified common image/video containers use ExifTool XMP fields; MP3 uses ID3 and retains the compressed audio bytes. Unsupported containers, failed safe writes, and MP3 files above 64 MiB preserve original media and use the authoritative sidecar; the reason is recorded. External files without sidecars are also indexed from embedded metadata. ExifTool workers are closed after each operation. Distributable builds must unpack/verify the vendored executable resources.
- **Audio waveforms:** the host validates scope plus indexed audio asset ID before decoding. FFmpeg streams mono floating-point samples at 8 kHz into 100 peak buckets; renderer memory never contains the full recording. Operations are serialized, bounded by a timeout, and closed with the media adapter. The 64-entry cache includes file path, size, modification time, and change time, so externally replaced audio is recomputed. The input decoder allows local file/pipe protocols only. A real 115 MB WAV test verifies non-flat waveform shape and changed-file cache invalidation. This replaces the browser decoder, whose previous size cap and content policy prevented reliable previews. [FFmpeg resampling reference](https://ffmpeg.org/ffmpeg-filters.html#aresample).
- **Vendor-derived files:** initial project ignore rules include renders and thumbnail/transcode/waveform caches. The media adapter migrates existing projects idempotently with exact directory rules; `.hyperframes` manual-edit/motion manifests remain tracked editing source. Generated cache files must not dirty a project or invalidate a freshly rendered export.
- **Rendered output:** the project manifest stores a portable relative path, validated to exist inside that project, plus the source-index fingerprint at render completion. The fingerprint excludes only `.vandashi.yml`, `video_packaging.yml`, and `launch.yml`; tracked composition/script/assets changes invalidate the export. Dirty source files also hide the export until saved and rendered. Existing video files remain recoverable, but exports without the fingerprint must be rendered again before publishing. Packaging/release bookkeeping changes preserve a valid export. Rendering output is derived and ignored by Git; the manifest and editing source are tracked.
- **Brand images:** picker-selected absolute image paths are authorized at IPC, copied to `brand_identity/brand_icon.<extension>` in the confirmed manual save, and stored in YAML as relative filenames. Files are committed with the rest of that save. The original is untouched. Existing relative image paths must remain within identity. Native-selected draft images can be previewed through the same media scheme, with the selection capability revalidated on each request.
- **Metadata manual saves:** the asset inspector uses the shared editable AI commit-confirmation dialog and submits the reviewed title/body to the asset repository. Failed saving keeps the draft and confirmation available. Copied shared assets cannot be edited from a video, including through the selected-asset AI shortcut; edit their authoritative shared-library entry. The asset page refreshes on entry and when focus returns from an external editor, unless a draft or operation is in progress.
- **Verification:** `tests/storage.test.ts`, `tests/storage-assets.test.ts`, and `tests/git.test.ts` exercise actual temporary files and Git repositories, PNG XMP round trips, MP3 tag round trips with byte preservation, recovery backups, independent repositories, stale drafts, path escapes, shared-copy conflicts, original-byte deduplication, persistent checkpoints, history pagination, hook isolation, and restoration. Cross-platform packaged-app behavior is not inferred from these local tests.

## Desktop boundary review and fixes (2026-09-23)

The review first traced main-process IPC, preload exports, native file selection, media protocol requests, and settings persistence. The requested fixes were then implemented separately. Primary reference: [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security), especially IPC sender validation, sandboxing, navigation, and limiting exposed APIs.

| Finding                                             | Initial risk and reachability                                                                                                                                                                                                                                               | Resolution and verification                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Arbitrary renderer-supplied import/inspection paths | High impact if trusted renderer code is compromised: `describeAsset`, attachments, and import APIs could inspect or copy local paths that the user never selected. The public API had no selection check before reaching the host/agent.                                    | `src/desktop/validation.ts` maintains canonical native-selection grants. `src/desktop/main.ts` authorizes input paths before dispatch. Native pickers grant files/directories; `pathForFile` grants only a path obtained from Electron's native `webUtils` for an actual File. Pending grants are awaited to preserve drop/import ordering. Tests reject unselected external files, permit selected ones, and reject changed symlink targets.                                                                                          |
| Same frame trusted without checking loaded location | A main frame that somehow navigated elsewhere would retain the frame identity used by the old guard. Existing navigation denial reduced reachability but was not a complete identity check.                                                                                 | `src/desktop/validation.ts` requires matching web contents, top-level frame, and exact expected renderer location. Production ignores development URL overrides; development URLs must be loopback. Navigation, popups, and webviews are denied. Permission requests/checks default to denied; the only exception is sanitized clipboard writing from the exact top-level app WebContents and expected document, verified by native History-copy regression. Reads, Studio frames, other windows, and unknown permissions stay denied. |

Non-findings: renderer has no Node integration or generic filesystem/shell API; preload does not pass the privileged IPC event to callbacks; Electron 44's current clipboard API is used; actual build output is `out/main/index.js` plus `out/preload/preload.cjs`, matching startup/preload paths. Native E2E confirmed the 1200×720 minimum and absence of renderer `require`/`process`. Scope excludes a complete audit of third-party Electron/Chromium, ExifTool, Hyperframes, Codex, platform websites, and OS-specific packaged distribution behavior.

Native closing now respects renderer `beforeunload` protection for dirty drafts, active operations, and the manual editor. The native dialog defaults to keeping work open. Agent/media disposal runs only after closure is allowed; the final quit is deferred to the next event-loop turn so Electron does not silently ignore a reentrant quit. A native Electron test verifies both keeping the window alive and actually exiting after explicit confirmation. These are English source strings; translations intentionally wait for feature completion.

The private Studio host bridge targets only a direct child frame on the registered `http://127.0.0.1:<port>/#project/<id>` origin/project. It installs the version-pinned fetch/event bridge and flushes pending native editor changes before Git inspection/save/discard. No Node, IPC, arbitrary-script, or host bridge method is exposed through the public renderer API. Origin, project, path, credentials, and parent-frame mismatch cases are tested. Actual Studio save timing remains part of the media integration's native verification.

The shared asset pane uses its actual available container width for layout: below 560 px, the library and inspector stack with their own scrolling regions; below 390 px, the import action wraps. This preserves usable asset controls when the chat divider reaches 75% at the native 1200×720 minimum. A real Electron geometry regression verifies both panels remain aligned, within the window, and free of horizontal content overflow.
