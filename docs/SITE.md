# Landing page

The site is built after the English app checkpoint and the seven-language desktop
integration. Its source is `landing/src`; the production output is `dist/landing`.
Vite uses `/Vandashi/` and MPA mode so missing files produce real 404 responses.
The intended GitHub Pages address is `https://igormidev.github.io/Vandashi/`;
deployment must be observed before treating that address as a live result.

## Design and content

The page opens with one large genuine Creation workspace image. Its pale canvas
(`#f7f9f8`), dark text (`#16211d`), muted text (`#596760`), deep green action
(`#155c45`), and mint image surround (`#d0ebdf`) frame the app's dark workspace.
Geist carries display and body text; bundled Noto fonts cover Japanese and Korean.
The three supporting stories describe creative guides, reusable assets, and clips.
They use alternating image proportions instead of a repeated card grid.

The design applies the researched
[Anthropic frontend-design guidance](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)
and [Vercel interface guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md).
Headlines use sentence case; copy names actual product behavior. The only motion
is user-driven scrolling and a short modal backdrop transition, with reduced-motion
support. Small screens stack the stories and can open and pan a full-size screenshot.
Screenshot dialogs return focus and support Escape, keyboard arrows, and touch scrolling.

Vandashi software is free and open source. AI consumes the user's own Codex allowance.
The site deliberately identifies the development preview and source installation;
it does not advertise available signed installers, unlimited AI, or verified uploads.
The English installation prompt matches README. All locales preserve its commands,
official-source installation, direct sign-in, and existing-project safeguards.

## Languages

`landing/src/locales` contains 40 keyed strings per language: English, Japanese,
French, Spanish, German, Korean, Brazilian Portuguese, and Italian. These catalogs
are separate from the desktop catalogs because their content and consumers differ.
Japanese/Korean and French/Spanish/Italian were authored in focused contexts using
the complete genesis brief and actual site components. German/Portuguese received
a separate read-only editorial review and corrections. No language files are
generated by translating existing user project content.

`language.ts` selects the first supported value from the URL's `lang`, the saved
choice, and the ordered browser preferences, then English. All Portuguese regions
map to `pt-BR`. Invalid tags and blocked browser storage are handled independently.
Language changes update page metadata, HTML `lang`, accessible labels, the URL,
and the selectable installation prompt. A failed copy always opens that prompt,
including after the user closed it following an earlier failure.

## Screenshot provenance

All four PNGs in `docs/screenshots` are unmodified captures of the real unsigned
macOS ARM64 app built from `6795514`, opened with the disposable Northstar Stories
manual-integration workspace on 2026-09-23. Each is 2960×1880 pixels. The composition,

The WebP equivalents in `landing/src/assets` are lossless encodings made with
`cwebp -lossless`. They preserve all pixels and dimensions. The icon derives from
`build/icon.svg`. App screenshots remain English; captions and descriptions are
translated. Recheck them after structural or visible app changes.

## Verification and deployment

- `npm run check` checks both strict TypeScript environments, translation/accessibility
  lint, import boundaries, unit tests, and both production builds.
- `npm run test:site` builds the production bundle and starts an exclusive preview at
  `http://127.0.0.1:4174/Vandashi/` for Chromium, Firefox, and WebKit. Site tests remain
  separate from native Electron tests.
- Browser scenarios cover all eight languages at 320×568, 375×812, 390×844,
  768×1024, 1024×768, 1440×900, 1920×1080, and 844×390, plus enlarged text,
  reduced motion, localization, keyboard/modal/copy behavior, denied capabilities,
  asset loading, and production base-path failures.
- `.github/workflows/pages.yml` verifies source, language contracts and browser
  behavior before uploading the tested artifact. The default branch deploys through
  the `github-pages` environment with narrowly scoped Pages/OIDC permissions.
  Repository Pages must use GitHub Actions as its source.

The base path follows [Vite's Pages deployment instructions](https://vite.dev/guide/static-deploy.html#github-pages),
and workflow permissions follow [GitHub's custom-workflow documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
Automated configuration is not evidence of a live deployment. Final results belong
in the acceptance checklist and manual verification journal.

## Verified local checkpoint — 2026-09-23

The final local production browser run passed all **306 cases** across Chromium,
Firefox and WebKit in 1.3 minutes. The language and catalog suite passed **58 tests**.
Independent review inspected 20 full-page/dialog captures and then rechecked 15
refreshed captures after the German/Japanese heading corrections. All 72 automated
captures were regenerated from the tested production build. Enlarged text is covered
by interaction/layout assertions; those captures do not separately depict 200% text.

The suite found real enlarged-text header overflow and WebKit keyboard-panning
defects, both corrected and verified. Direct browser use separately verified the
actual clipboard setup prompt, language selection, mobile enlargement and dismissal.
Full PNG/WebP comparisons confirm all four encoded screenshots are pixel-identical
to their source captures. Source-boundary negative probes reject Node/host imports
into the landing page and landing imports into the desktop app. GitHub Pages
deployment was subsequently verified as recorded below.
